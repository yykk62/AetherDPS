# AetherDPS – Hinweise für Claude

Ein quelloffener DPS-Meter für AION 2 (EU), deutsch zuerst, in 10 Sprachen, als Fork von RATmeter (GPL-3.0). Hieß bis 0.5.0 „Aion2Meter“ (Übergang: `LegacyMigration`, Mutex-Name; das zusätzliche Release-Asset `Aion2Meter.exe` entfällt seit 0.7.10).

- **Lesen:** `docs/WARTUNG.md` (Aufbau, Upstream-Merge, Patch-Liste), `docs/PROTOKOLL.md`, `docs/PLAN.md` (nächste Schritte)
- **Bauen und testen:** `dotnet build AetherDPS.slnx`, `dotnet test AetherDPS.Tests`. Es braucht das .NET-10-SDK. `dotnet` liegt nicht im PATH, also den vollen Pfad `C:\Program Files\dotnet\dotnet.exe` verwenden.
- **Oberfläche ohne Bildschirm prüfen:** `dotnet test AetherDPS.UiTests` rendert alle Fenster unsichtbar. Mit `AETHERDPS_SHOTS=<ordner>` werden die Bilder gespeichert. So lässt sich das Aussehen prüfen, ohne dass Fenster über einem laufenden Spiel aufgehen
- **README-Bilder** (`docs/media/`): `AETHERDPS_README=<ordner>` (+ `AETHERDPS_README_FROM=%LOCALAPPDATA%\AetherDPS` für den eigenen Charakter mit echtem Profil, ausdrücklich so gewünscht), `dotnet test AetherDPS.UiTests --filter ReadmeMedia`, dann `python tools/readme-media.py <ordner>`. Mitspieler nur mit Pseudonymen, nie fremde echte Namen; der eigene Name steht nie im Code
- **Nie echte Fenster öffnen, solange AION2.exe läuft** (der Nutzer spielt dann). Wiedergaben laufen mit eigenem Datenordner
- **Ohne Spiel testen:** `aetherdps-cli demo x.txt`, danach `AetherDPS.exe --replay x.txt`
- **Upstream-Dateien** (`AionDpsMeter.*`) nur minimal ändern und jede Änderung in die Tabelle in `docs/WARTUNG.md` eintragen
- **Mitschnitte** enthalten Spielernamen. Sie werden nie committet und nie öffentlich geteilt.
- **Texte** in der Oberfläche stehen in `AetherDPS.App/Lang/de.json` (Quelle) und den anderen Sprachdateien und werden über `{l:T schlüssel}` bzw. `Loc.T()` eingebunden (auch in der Engine). Keine fest eingebauten Texte. Neue Schlüssel in **alle** Sprachdateien eintragen, prüfen mit `python tools/check-lang.py`.
- **Was nach außen geht, ist abschließend:** Update-Prüfung, status.json lesen, der tägliche Nutzungszähler (nur mit Zustimmung, nur `{v, lang, new}`), Fehlerberichte (nur per Klick, Namen entfernt), Discord-Webhook (nur per Klick, eigene URL), Discord Rich Presence (`Community/DiscordPresence.cs`, nur mit Zustimmung `DiscordPresence`, nur lokal über die Pipe `\\.\pipe\discord-ipc-N` an den Discord-Client: Zustand wie „Dungeon: …“/„Bosskampf: …“, Dungeon-/Bossnamen abschaltbar, nie Spieler- oder Charakternamen; Client-ID 1560475211114090566, Bild-Asset `logo` im Developer Portal; ohne Fenster prüfen mit `aetherdps-cli presence demo`) und Charakter-Profile bei NCSOFT (`Community/Armory.cs`: Name + Server an die offizielle Such-/Profil-API, nur wenn der Nutzer den Reiter Profil öffnet, sucht/klickt, – abschaltbar, `PartyJoinPopup` – jemand der Gruppe beitritt oder – abschaltbar, `ProfileHistory` – alle 4 Std. das eigene Profil für den lokalen Verlauf (`Community/ProfileHistory.cs`); Bilder nur von assets.playnccdn.com und profileimg.plaync.com, Skill-/Item-Bilder einmal geladen und im Datenordner `Bilder` aufbewahrt, auch für Kampfanalyse und Overlay). Auf der Webseite: „Mein Charakter“ (`web/src/pages/charakter.astro`, Name + Server nur im localStorage) fragt bei jedem Besuch `GET /api/character` am Worker (`server/src/character.ts`), der dieselben NCSOFT-Abfragen macht (region=eu, lang=de-DE), 1 Std. cacht, NCSOFT höchstens 1×/s fragt (ToS §6), je IP 10 Abrufe/Min. erlaubt und nichts darüber hinaus speichert. Alles in `Engine/Community/CommunityService.cs`, der Server in `server/`. Nichts darüber hinaus (keine Kampfdaten, keine Bestenlisten, keine IDs), und jede Änderung daran in README und Datenschutzerklärung nachziehen.
- **Webseite (`web/`)**: Astro, statisch, Cloudflare Worker `aetherdps-web`, live unter aetherdps.com. Mails an @aetherdps.com leitet Cloudflare Email Routing an den Nutzer weiter. Bauen mit `npm run build` in `web/`, ansehen mit dem Launch-Eintrag `web` (Port 4321), veröffentlichen mit `npm run deploy` nur nach Rückfrage. Spieldaten liest die Seite beim Bauen aus `AetherDPS.Engine/GameData`, Bilder kopiert `scripts/sync-assets.mjs` nach `public/gen/` (nicht im Repo). Texte in `web/src/i18n/de.json`. Name und Anschrift fürs Impressum stehen nur in `web/.impressum.json` (gitignored), ohne die Datei bricht der Build ab. Cheat Sheet, Checkliste und Event-Zeiten stammen mit Erlaubnis von Wakayashi (wakayashi.gg): überall, wo sie genutzt werden, nennen und verlinken (`Credit.astro`). Die Seite setzt keine Cookies und lädt nichts von fremden Servern, außer auf „Mein Charakter“ die Profilbilder und Icons von NCSOFT; was sie im Browser speichert, bleibt dort
- **Server (`server/`)** ist ein Cloudflare Worker (Konto des Nutzers, `wrangler deploy` aus `server/`). Statistik und Fehlerberichte: `/admin?key=…`, Schlüssel in `~/.secrets/aetherdps.env` (nie ins Repo). Offene Berichte abarbeiten: `GET /admin/api/reports?key=…&status=open`.
- **Discord (`discord-bot/`)**: Worker `aetherdps-discord` auf bot.aetherdps.com (Rollen-Knöpfe, AION-2-News und Releases alle 15 Min. automatisch), Einrichtungs-Skripte und Grafiken, siehe `discord-bot/README.md`. Bot-Token nur in `~/.secrets/aetherdps.env` und als Worker-Secret. Releases landen über die GitHub-Release-Notizen (also `CHANGELOG.md`) automatisch in #ankündigungen
- **Nachrichten an alle** (z. B. „Update kommt heute Abend“): Eintrag in `status.json` auf main pushen (`messages[]` mit `id`, `level` info/warn, `text` je Sprache, optional `until`, `minVersion`, `maxVersion`); Discord-Link als `discord`. Nur nach Rückfrage beim Nutzer pushen.
- **Beim Testen** kein hörbarer Ton, und die Test-Instanz der App danach beenden
